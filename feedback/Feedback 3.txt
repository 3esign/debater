Love the ambition here. Let me be direct: this plan is about 40% excellent ideas and 60% beautiful distractions that will kill the project before launch. Here's my ruthless audit, followed by what I'd actually build.

What's genuinely great:
The core hook is electric — "two AIs debate, a smart contract settles it." That's a real product. The Solidity viewer with state-driven highlighting is clever differentiation. The rhythmic token streaming is a must-have polish detail.
What will sink you:
1. Six LLM providers on day one is a trap. Gemini + OpenAI + Anthropic + OpenRouter + Groq + Ollama means you're writing six streaming clients, six error paths, six key UX flows — before you've validated that anyone wants the core product. Groq and Ollama especially are edge cases. Ship with Anthropic + OpenRouter (which gives you Gemini, DeepSeek, Llama through one API). Add others after you have users.
2. The Solidity viewer is a vibe, not a feature. A real commit-reveal-quorum voting contract is a brilliant narrative anchor, but nobody will actually deploy it to Base. You're building a UI that glows at a contract that never gets called. That's fine — but call it what it is: a simulator. Don't let the Solidity complexity eat your frontend polish time.
3. "Shareable Receipt" is Phase 1, not Phase 5. This is your virality mechanism. If someone shares a receipt, that's your acquisition loop. It should be the first thing you design, not an afterthought after the betting sidebar.
4. The betting sidebar is complexity debt. Wagers, commit hashes, quorum reveals — this is a lot of state for a v1. Users want to watch the debate and feel something. Start with a simple "vote for who's winning" pulse, not a full prediction market.
5. page.tsx doing Lobby + Arena + Receipt is a disaster. Split these. The routing story matters for shareability too (you want /debate/[id] URLs).

Three specific things to fix in your plan today:
Rename your file structure. page.tsx doing three jobs is a red flag. You want:

app/page.tsx → lobby only
app/debate/[id]/page.tsx → arena
app/debate/[id]/receipt/page.tsx → shareable receipt as its own route (OG image generation too)

Reframe the Solidity viewer copy. Call it "simulated contract" or "contract sandbox" in the UI. This removes the implicit promise that real transactions are happening, which will confuse and frustrate users who try to verify on-chain. It also makes the product more honest and the "what if this were real" angle more interesting.
Your lib/llm.ts interface should be this simple:
typescriptinterface DebateAgent {
  name: string;
  model: string;
  provider: 'anthropic' | 'openrouter';
  persona: string;
}

async function* streamTurn(agent: DebateAgent, history: Message[]): AsyncGenerator<string>
One function. One interface. The provider routing lives inside that function, invisible to the rest of the app. Don't let provider complexity leak into your components.
The bones of this project are genuinely great. The neon theme + Solidity glow + rhythmic streaming is a coherent aesthetic identity that nobody else has. Just don't bury the live debate under six layers of speculative infrastructure. Ship the colosseum first — the betting market can come after there are spectators.
